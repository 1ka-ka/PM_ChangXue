## 2. 全局约定

### 2.1 API 响应信封

```jsonc
// 成功
{ "code": 0, "msg": "ok", "data": { } }
// 失败
{ "code": 40101, "msg": "账号或密码错误", "data": null }
```

HTTP 状态码统一 200（业务错误用 code 区分）；仅 401（未登录/token 失效）与 500（服务器异常）使用真实 HTTP 状态码，便于前端拦截器统一处理。

### 2.2 错误码分段

| 段     | 模块                                                        |
| ----- | --------------------------------------------------------- |
| 0     | 成功                                                        |
| 400xx | 通用参数/校验错误（40001 参数错误、40002 资源不存在、40003 内容含违禁词）            |
| 401xx | 认证（40101 账号或密码错误、40102 token 失效、40103 账号已封禁）              |
| 403xx | 权限（40301 无权操作、40302 非管理员）                                 |
| 409xx | 业务规则冲突（40901 采纳数已达上限、40902 积分不足、40903 重复点赞/举报、40904 重复回答） |
| 500xx | 服务器错误                                                     |

### 2.3 认证

- 登录签发 JWT（HS256），payload：`{ "sub": user_id, "role": "user|admin", "exp": ... }`

- 请求头：`Authorization: Bearer <token>`

- 需登录接口标注 🔒；管理员接口标注 🔒 admin；其余为公开接口

- 封禁账号请求一律返回 40103

### 2.4 分页约定

- 请求：`?page=1&page_size=20`（page\_size 上限 50）

- 响应：`{ "items": [...], "total": 123, "page": 1, "page_size": 20 }`

### 2.5 软删除与可见性

- 所有 UGC 表（post/answer/comment）使用 `deleted_at`（NULL=可见）

- 全部列表/详情/搜索/知识库查询强制追加 `deleted_at IS NULL`

- 已删除内容访问返回 40002，文案"内容不存在或已删除"

### 2.6 通用对象类型枚举

`target_type`: `1=帖子 2=回答 3=评论`（点赞/收藏/举报/通知复用）

### 3.5 预留表（P0 不建，P1/P2 建表时按此评审）

| 表                             | 版本        | 要点                                                                                    |
| ----------------------------- | --------- | ------------------------------------------------------------------------------------- |
| shop\_goods / exchange\_order | P1（仅契约评审） | goods: type(虚拟/实物)、price、stock、status；order: user\_id、goods\_id、credit\_log\_id（事务关联） |

### 3.6 关键约束实现说明

| 约束      | 实现方式                                                                                  |
| ------- | ------------------------------------------------------------------------------------- |
| 积分不透支   | `balance >= 0` CHECK + 服务层 `SELECT ... FOR UPDATE` 行锁（SQLite 用 `BEGIN IMMEDIATE` 串行写） |
| 点赞/收藏幂等 | 联合主键，插入冲突即判定已操作                                                                       |
| 每帖最佳唯一  | 服务层事务内"先清后置" + MySQL 部分唯一索引兜底                                                         |
| 日产出封顶   | `credit_log` 按 `(user_id, created_at)` 索引聚合当日 `source IN (1,2,3,4)` 正向流水求和            |
| 二层评论封顶  | `comment.parent_id` 非 NULL 时校验目标为根评论（parent\_id IS NULL），否则拒绝                         |

## 6. 关键流程接口编排（服务端事务边界）

### 6.1 采纳（接口 17）——单事务

```
BEGIN
  1. 锁定 post 行 → 校验: 请求者==author_id, post 未删
  2. 锁定 answer 行 → 校验: 未删、未采纳、所属本帖
  3. 统计本帖已采纳数 < ACCEPT_MAX
  4. answer.is_accepted = 1
  5. 若 post.status == 0:
       post.status = 1, accepted_at = now
       INSERT knowledge_item(post_id)      -- 冲突则忽略（幂等）
  6. credit.grant(回答者, source=采纳, +30)   -- 见 ARCH §7.1，封顶则记 note 不发放
  7. gratitude_stat 三 period 各 +30
  8. INSERT notification(回答者, type=被采纳)
COMMIT
```

### 6.2 发帖悬赏（接口 9）——单事务

```
BEGIN
  1. 校验 tag_ids 数量与 enabled
  2. 若 reward > 0: credit.deduct(作者, source=悬赏, -reward)  -- 行锁，不足抛 40902 整体回滚
  3. INSERT post + post_tag
  4. 记录 post_publish_step 埋点（同步写，异步可）
COMMIT
```

### 6.3 推荐排序（接口 13，recommend Tab）

```
score = heat + reward_weight - decay
heat         = answer_count×3 + like_count×2 + view_count×0.1
reward_weight = reward / 10                       -- 100 悬赏 +10 分
decay        = IF(status=0 AND created_at < NOW()-14d, 50, 0)
排序: score DESC, id DESC    -- P0 简化公式，参数与权重进 app_config
```

## 7. 安全与实现规范

| # | 规范                                                                                                   |
| - | ---------------------------------------------------------------------------------------------------- |
| 1 | 密码 bcrypt cost=12；API 永不返回 password\_hash 与完整 phone（脱敏 `138****1234`）                                |
| 2 | 上传文件：扩展名白名单 + 内容头校验（magic bytes）+ 随机重命名；目录禁止执行权限                                                     |
| 3 | 全部 UGC 输入（帖子/回答/评论/昵称/举报说明）过敏感词库（DFA 实现，词库文件 `resources/sensitive_words.txt` 可热更新）；命中返回 40003，不回显具体词 |
| 4 | 管理接口双重校验：JWT role=admin + 中间件白名单路由                                                                   |
| 5 | SQL 一律 ORM 参数化，禁止字符串拼接                                                                               |
| 6 | 埋点接口限流（IP 维度，简单内存令牌桶 60 次/分钟）                                                                        |
| 7 | 图片经服务端压缩（Pillow，最长边 1280px，质量 80）后存储，原图丢弃                                                            |
