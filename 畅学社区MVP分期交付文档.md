## 1. 开发流程规则（每阶段必须遵守）

1. **单一增量原则**：一个阶段 = 一个可独立验证的功能块；不做阶段外的"顺手实现"。
2. **测试先行**：每阶段先按技术细节文档 §8 用例组编写测试（pytest），测试失败→实现→测试全绿→阶段完成。禁止"先写完再补测试"。
3. **文档同步**（强制，不可跳过）：

   - 每阶段完成 → 更新 `PROJECT_STATE.md`（进度、已知问题、下一步）

   - 发现 PRD/ARCH 与实现冲突 → 修正实现或走文档修订（PRD 总册修订记录 + ARCH 迭代记录），**不允许文档与代码脱节**

   - 架构变更（目录/模块/表结构/技术选型）→ 更新 ARCH.md 并追加迭代记录
4. **增量可回退**：每阶段一个 git 提交序列（feat + test 分离），出现阻塞可回退到上一阶段末状态。
5. **阻塞上抛**：阶段内无法解决（技术阻塞/需求歧义）→ 停止，记录到 PROJECT\_STATE.md 已知问题区，不硬编码绕过。
6. **验收命令**：每阶段交付物必须能用一条命令验证（`pytest`、`uvicorn 启动 + curl`、`npm run build` 等）。

## 2. 阶段总览与依赖

```
S0 骨架 ──> S1 建表 ──> S2 认证 ──> S3 积分核心 ──> S4 发帖 ──> S5 互动 ──> S6 采纳 ──> S7 广场搜索 ──> S8 通知榜单 ──> S9 治理后台 ──> S10 埋点契约 ──> S11 前端 ──> S12 联调部署
             (全量20表)   (TC-credit核心)          (依赖S3扣分)  (依赖S4)  (依赖S5)   (依赖S6知识库)
```

> 后端先行（S0-S10 全部 API + pytest 全绿），前端统一在 S11 接入（API 类型由 OpenAPI 自动生成，避免前后端并行导致的契约漂移）。
